# قالب المساعد الشخصي (assistant-template)

**ابنِ مساعدك:** في Claude Code اكتب `/plugin marketplace add Nfarahat99/assistant-builder` ثم `/plugin install assistant-builder@assistant-builder` ثم `/assistant-builder:build-assistant`. التفاصيل: [docs/START-HERE.md](docs/START-HERE.md).

قالب مساعد شخصي جاهز على **تيليجرام** (وواتساب اختيارياً) — صوت ونص بالعربي، مهام وتذكيرات وملخصات يومية، رسائل لأطراف ثالثة بعد موافقتك، وتعديلات كود عبر GitHub Actions. كل هوية المالك والمساعد تأتي من ملف واحد `assistant.config.json`؛ لا شيء مكتوب في الكود لشخص بعينه.

- **ابدأ من هنا (لغير المبرمجين، خطوة بخطوة):** [docs/START-HERE.md](docs/START-HERE.md)
- **دليل الإعداد الكامل (عربي، بالأوامر):** [docs/TEMPLATE.md](docs/TEMPLATE.md)
- **المرجع:** مبني من تجربة مساعد شخصي حقيقي ثم عُمّم (هوية من profile، نماذج لكل دور، تخزين ملفات، استضافة قابلة للتبديل).
- **نماذج الذكاء:** Gemini افتراضي لكل دور؛ Claude وأي مزوّد متوافق مع OpenAI يُختاران لكل دور من اللوحة (الإعدادات ← النماذج).
- **قاعدة صارمة:** لا شيء يُرسل لطرف ثالث ولا يُدمج أي PR بدون موافقتك الصريحة (`نعم N`).

> بقية هذا الملف يشرح سلوك المساعد وتفاصيله التقنية. أمثلة الأسماء والمستودعات أدناه توضيحية فقط.

ترسل له صوتية أو نص على رقم واتساب مخصص **أو على تيليجرام**، فيفهم كلامك بالسعودي ويحوّله لإجراءات:

- **مهام وتذكيرات**: "ذكرني أرسل العرض لسامي بكرة ٩ الصبح" ← تذكير في وقته.
- **ملخص يومي**: صباحاً (07:30) مهام اليوم والمتأخرة، ومساءً (21:30) مراجعة المفتوح.
- **رسائل لأشخاص (وضع link — الافتراضي)**: "قل لأحمد إني بتأخر" ← يرجع لك رابط `wa.me` بالنص جاهزاً؛ تضغطه وترسلها **من رقمك أنت**. رقم البوت لا يراسل أحداً غيرك إطلاقاً (حارس صارم في طبقة الاتصال بالوسيط يرمي خطأ لأي مستلم آخر) — الرقم حُظر سابقاً بعد ثوانٍ من أول رسالة لغريب.
- **الردود ترجع لرقمك، فمرّرها للبوت**: حوّل (Forward) رسالة الشخص أو صوتيته، أو أرسل **لقطة شاشة** المحادثة (Gemini يقرأ من قال ماذا)، أو الصقها: `رد أحمد: <نص رسالته>` ← ملخص + ٣ اقتراحات ← اختر 1/2/3 أو `رد: نصك` ← رابط wa.me جديد. إذا ما عرف الشخص يسألك.
- **تعديلات كود**: "عدّل في مشروع كذا: …" ← بعد موافقتك يشغّل Claude على GitHub Actions، ولما يجهز الـ PR يرسل لك ملخصه، ولا يدمجه إلا بعد "نعم".
- **ردود الناس**: إذا رد عليك شخص محفوظ (أو راسلته عن طريق البوت خلال ٣٠ يوماً) يحوّل لك رده مع ملخص واقتراحات رد: "1" / "رد: نصك" / "لا" — والإرسال دائماً بعد معاينة ونعم. الرسائل المتتالية خلال دقيقة تُجمع في تحويل واحد. الغرباء لا يُحوَّلون؛ يُذكرون في المراجعة المسائية ("وريني الرسائل" لعرضها). "وش قال أحمد؟" تعرض آخر المحادثة.
- **حارس الاتصال**: كل دقيقة يفحص اتصال رقم البوت. انقطاع > دقيقتين ← استئناف تلقائي (٢، ٥، ١٥ د)، ثم تنبيه على جوالك الشخصي عبر **ntfy** (خارج واتساب). إذا احتاج إعادة ربط يرسل لك صورة QR لتمسحها من جوال البوت. أثناء الانقطاع لا يرسل شيئاً للوسيط، وعند الرجوع يرسل لك ملخصاً واحداً بما فاتك.
- **جهات اتصال**: "احفظ رقم أحمد 0555…" مع مطابقة عربية ذكية (أ/إ/آ، ة/ه، ى/ي، "ال"، التشكيل).

> **قاعدة صارمة:** لا شيء يُرسل لطرف ثالث ولا يُدمج أي PR بدون موافقتك الصريحة على طلب محدد. الموافقة لازم تكون بعد المعاينة (بوقت واتساب)، وأرقام الطلبات لا تتكرر أبداً. الطلبات المعلّقة تنتهي بعد ٢٤ ساعة؛ طلب الدمج يُذكَّر به مرة، ثم يُسكَّر الـ PR.
> تغيير اسم رقم محفوظ يحتاج موافقة أيضاً، والرسائل تُقبل فقط إن وصلت على رقم المساعد (`session_phone`).

## كيف يعمل

```
جوالك ──واتساب──▶ رقم المساعد (مربوط في وسيط واتساب)
                      │  POST /webhook/wa  (موقّع HMAC-SHA256)
                      ▼
               المساعد (هذا المشروع)
   Gemini Flash: صوت+فهم باستدعاء واحد (احتياط عند 429/5xx: Flash-Lite)
   (اختياري: Groq Whisper للتفريغ إن كان متاحاً)
                      │
          Postgres: مهام، جهات، موافقات، طلبات كود
                      │
   POST /api/v1/messages ──▶ الوسيط ──▶ ردود لك / رسائل لأطراف ثالثة
   GitHub API ──▶ claude.yml ──▶ PR ──▶ دمج بعد موافقتك
```

## تيليجرام (قناة ثانية + احتياط)

كلّم البوت على تيليجرام مثل واتساب تماماً: نص، صوتيات، رسائل محوّلة، لقطات شاشة، والأوامر. الموافقات بأزرار (✅ نعم / ❌ لا / ✏️ عدّل، و1/2/3 للاقتراحات) كل زر مربوط برقم الطلب نفسه.
**الاحتياط التلقائي:** الرسائل الاستباقية (الملخصات، التذكيرات، طلبات الكود، التحويلات) تروح لواتساب إن كان متصلاً، وإلا لتيليجرام فوراً. إذا انقطع واتساب يبلغك تيليجرام فوراً بالسبب، ويرسل رمز QR كصورة إذا احتاج ربط، ورسالة واضحة إذا انحظر الرقم.

**الإعداد:**
1. افتح [@BotFather](https://t.me/BotFather) في تيليجرام ← `/newbot` ← اختر اسماً ومعرّفاً ينتهي بـ `bot` ← انسخ التوكن إلى `TELEGRAM_BOT_TOKEN`.
2. (اختياري) `/setprivacy` ← Enable، و `/setjoingroups` ← Disable.
3. ولّد رمز ربط: `openssl rand -hex 12` ← `TELEGRAM_LINK_CODE`.
4. انشر، ثم افتح البوت في تيليجرام وأرسل: `/start <الرمز>` ← أول محادثة ترسل الرمز الصحيح تصبح المالك (يُحفظ). أي شخص آخر يُتجاهل.
5. على ريلواي الويبهوك يُضبط تلقائياً (`setWebhook` مع `secret_token`) من `RAILWAY_PUBLIC_DOMAIN`؛ بدون رابط عام يعمل بالاستطلاع (long polling).

## ذاكرة البوت وصدقه

- `knowledge/owner.md` (من هو المالك، لماذا وُجد البوت، قدراته وحدوده) تُحقن في كل استدعاء للنموذج مع المالك، تليها **حقائق حية** (GitHub، القنوات، حالة واتساب، المشاريع، آخر الطلبات) — الحية تعلو عند التعارض. نسخة قابلة للتعديل في قاعدة البيانات (`kv.knowledge_md`) تُزرع من الملف أول مرة وتُقرأ في كل استدعاء (للوحة التحكم).
- **قاعدة الصدق:** البوت لا يقول أبداً إنه أصلح أو عدّل شيئاً إلا بإجراء فعلي؛ أي خلل فيه أو ميزة له = اقتراح طلب كود على مستودعه.
- رسالة واحدة لكل رد، ولا مسارات محلية (`C:/…`) في أي نص يراه المالك.
- النسخة: `scripts/version.mjs` يكتب `version.json` عند الإقلاع من `GIT_SHA`/`RAILWAY_GIT_COMMIT_SHA` أو git، وإلا يُسأل GitHub عن آخر commit.

## الحماية من حقن التعليمات

رسائل الأطراف الثالثة **بيانات فقط**: لا تمر أبداً بفهم أوامرك، ولا تُنشئ إجراءات، ولا توافق على شيء، ولا تغيّر الجهات. تحليلها باستدعاء منفصل مخرجه ملخص واقتراحات نصية فقط، ونصها ملفوف بعلامات عشوائية لكل استدعاء، ولا يدخل سجل المحادثة الذي يراه نموذج أوامرك. أي رد عليهم يمر بمعاينة ← نعم منك.

## حارس الاتصال (يتطلب فرع `feat/session-selfheal` في الوسيط)

يستخدم `GET /api/v1/status` و `POST /api/v1/session/resume` و `POST /api/v1/session/relink` و `GET /api/v1/session/qr?format=png`. الحالة تظهر في `/health` تحت `wa`. رموز QR في واتساب تتجدد كل دقيقة تقريباً — إن انتهت صلاحية الصورة افتح رابط اللوحة في التنبيه.

> **ملاحظة على الخصوصية:** الخطط المجانية لدى Google قد تستخدم المحتوى لتحسين منتجاتها. إن كان هذا مقلقاً فعّل الفوترة أو اجعل `LLM_PROVIDER=groq`.

## قواعد بيانات المشاريع من المحادثة (db_query / db_write)
`DB_CONNECTIONS` = مصفوفة JSON: `[{"key":"falak","name_ar":"نبراس","aliases":[],"project":"falak","url":"postgresql://…","deny_tables":[]}]` (بدون أسرار في المستودع — المتغير على Railway فقط).
- **القراءة:** النموذج يكتب SELECT واحدة من المخطط (جداول/أعمدة، مخزّن ١٠ دقائق، بلا `deny_tables`) ← حارس نصي (جملة واحدة، لا DML ولا CTE كاتبة ولا SELECT INTO ولا FOR UPDATE ولا دوال خطرة) ← `BEGIN TRANSACTION READ ONLY` + `statement_timeout=10s` ← ROLLBACK، حد ٥٠ صفاً، والأعمدة `pass|hash|token|secret|otp|key|cred|session` محجوبة (حتى مع AS).
- **الكتابة:** INSERT/UPDATE/DELETE فقط ← تجربة ثم ROLLBACK (العدد + ٥ صفوف) ← معاينة ← «نعم N» صريحة ← تنفيذ يُلغى إذا تغيّر العدد. أكثر من ٥٠٠ صف يُرفض ما لم يذكر المالك العدد.
- كل شيء في جدول `db_audit`. المفتاح `db_access` في لوحة التحكم يوقف الميزة.

## قواعد بيانات المشاريع (قراءة فقط)
عرّف كل قاعدة بمتغير بيئة `PROJECT_DB_<الاسم>_URL` (يُفضّل دور Postgres بصلاحية SELECT فقط). عبر لوحة التحكم (بعد تسجيل الدخول):
`GET /api/dash/projectdb` (الأسماء فقط) · `GET /api/dash/projectdb/:name/schema` · `POST /api/dash/projectdb/:name/query` بجسم `{"sql":"select …","limit":50}`.
الحماية: معاملة READ ONLY، جملة SELECT/WITH/EXPLAIN/SHOW واحدة فقط، مهلة ٨ث، حد ٢٠٠ صف، حجب قيم أعمدة password/token/secret/hash…، ولا تُعاد عناوين الاتصال أبداً.

## projects.json

مصفوفة مشاريع (يولّدها مستودع `claude-config`؛ نسخة تجريبية مرفقة):

```json
[{ "folder": "myapp", "repo": "owner/myapp", "default_branch": "main",
   "aliases": ["تطبيقي"], "railway_project": "myapp" }]
```

عند الإقلاع يُقرأ `PROJECTS_FILE`، ثم إن وُجد `GITHUB_TOKEN` يُحمّل من `PROJECTS_REMOTE` (أو `github.projects_remote` في الإعدادات) ويعلو على المحلي.

**مطلوب في كل مستودع هدف:** workflow باسم `claude.yml` يقبل `workflow_dispatch` بمدخلين `prompt` و `request_id`، وينشئ فرعاً باسم `claude/req-<request_id>` ويفتح منه PR. ويجب أن يكون `run-name: "claude <request_id>"` — البوت يطابق التشغيل بهذا فقط (لا تخمين بالأحدث).

## النشر على ريلواي

1. `railway init` (أو من اللوحة: New Project ← Deploy from GitHub ← مستودعك المنشأ من القالب).
2. أضف إضافة **Postgres** — تملأ `DATABASE_URL` تلقائياً.
3. اضبط المتغيرات: `WEBHOOK_SECRET`، `GATEWAY_URL`، `GATEWAY_API_KEY`، `ASSISTANT_PHONE`، `OWNER_PHONE`، `GEMINI_API_KEY`، `GITHUB_TOKEN` (والباقي اختياري — `GROQ_API_KEY` اتركه فارغاً).
4. انشر. `railway.json` يستخدم الـ Dockerfile وفحص الصحة على `/health`. الجداول تُنشأ تلقائياً.
5. من Settings ← Networking ← **Generate Domain** لتحصل على رابط عام.

> خدمة واحدة فقط (replica = 1): المجدول ومتابعة الطلبات يعملان داخل العملية.

## ربط الوسيط بالبوت

بعد ربط رقم المساعد في لوحة الوسيط (مسح QR)، سجّل الويبهوك:

```bash
curl -X PUT "$GATEWAY_URL/api/v1/webhook" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<bot>.up.railway.app/webhook/wa",
    "secret": "<نفس WEBHOOK_SECRET>",
    "trusted_numbers": ["<OWNER_PHONE>"]
  }'
```

`trusted_numbers` يعطي ردود البوت لرقمك المسار السريع في الوسيط (بدون تباعد منع الحظر). الرسائل لأطراف ثالثة تمر بمحرك الحماية كالمعتاد — إذا كانت في نافذة الصمت الليلي يخبرك البوت متى بتنرسل.

### عقد الويبهوك

```
POST /webhook/wa
X-Meem-Event: message
X-Meem-Signature: sha256=<hex HMAC-SHA256(الجسم الخام, WEBHOOK_SECRET)>
{ "event":"message", "message_id", "from":"9665…", "type":"text|audio|image|document|other",
  "text", "media":{"mimetype","base64","seconds","ptt","file_name"}, … }
```

- التوقيع يُتحقق منه على البايتات الخام بـ `timingSafeEqual` — توقيع خاطئ = `401`.
- أي رسالة من غير `OWNER_PHONE` تُسجّل وتُتجاهل.
- التكرار (نفس `message_id`) يُتجاهل — الوسيط قد يعيد المحاولة، فهذا آمن.
- `media` تحمل المفاتيح الخمسة دائماً (القيم قد تكون null).
- عند الإرسال يعيد الوسيط `eta_seconds` و`fast_lane` في رد 202؛ إذا كان التقدير أبعد من دقيقتين (وقت الهدوء) يقول لك البوت "بتوصل تقريباً الساعة HH:MM".
- الرد `200` فوري، والمعالجة في الخلفية بالترتيب.

## التطوّر الذاتي من المحادثات (مراجعة ليلية + تقييم)

> «لازم يكون دائماً قابل للتطور من المحادثات» — كل تعثّر يصير درساً محفوظاً وحالة اختبار لا تتكرر.

**المراجعة الليلية** (`src/selfreview`): كل يوم الساعة `self_review_at` (افتراضياً 23:30 بالرياض، والإيقاف من مفتاح `self_review` في الإعدادات) يمر البوت على محادثات اليوم ويكشف **حتمياً** (بلا نموذج):
تصحيحك («لا غلط»، «مو كذا»)، التذمّر («طولت»، «جاوبني على السؤال»، «ليش» القصيرة)، الطلب المتكرر (تشابه ≥٦٠٪ خلال ٣٠ دقيقة)، حلقات التوضيح (سؤالا خيارات متتاليان)، «تم» بلا إجراء مسجّل، الفشل/الاحتياط، و«ما لقيت/ما أقدر».
النموذج يجمّع ويلخّص فقط (وإن فشل: قواعد ثابتة). تصلك رسالة واحدة: `🪞 مراجعة اليوم: X محادثات، Y تعثّرات` + أهم ٣ (اقتباس + ماذا حصل + الإصلاح). ما يحتاج كوداً يصير طلب `code_change` معلّقاً على البوت مع مقتطف المحادثة كدليل — **لا يُنفَّذ إلا بـ «نعم N»**.

| تقول | يصير |
|------|------|
| `هذا غلط، المفروض <كذا>` (مباشرة بعد الرد الغلط) | تُحفظ حالة تقييم بتوقّعك (`eval_cases`, source=manual) |
| `مراجعة اليوم` | المراجعة الآن (نفس الرسالة الليلية) |
| `حالات التقييم` | عدد الحالات ومصادرها |
| `قارن النماذج` | يقيس الأساسي (NVIDIA) مقابل Gemini على كل الحالات — **النص على الاثنين، والصوت على Gemini وحده** (الإنتاج يفهم الصوت بـ Gemini دائماً). يحتاج المفتاحين |

**حالات التقييم**: كل حادثة تُحفظ في `eval_cases` (رسالتك + السياق + المتوقع: `action_types` المسموحة، `require_any`، `must_match`، `must_not` = `action:<نوع>` أو regex على الرد أو `payload:<regex>` على حمولة الإجراء). البذور (`src/evals/seed-cases.ts`) حالات مصطنعة تغطي أنواع التعثّر الشائعة، ومعها حالات عمر E1–E10.

**التشغيل**:
```bash
npm run eval                         # البذور على النموذج الحقيقي (GEMINI_API_KEY / NVIDIA_API_KEY من البيئة) ← جدول + eval-report.json
npm run eval -- --from-db            # + حالات القاعدة (المراجعة الليلية ومن «هذا غلط»)
npm run eval -- --compare            # الأساسي مقابل الاحتياطي (نص/صوت منفصلان)
npm run eval -- --only E5 --md out.md
EVAL_MIN_SCORE=80 npm run eval       # خروج 1 تحت 80%
```
التقييم يقيس **خطوة الفهم الخام** (understand + البرومبت الحقيقي) قبل حواجز ما بعد الرد في llmPath (src/lib/reply-guards.ts) — مقصود: يقيس النموذج والبرومبت نفسيهما، والحواجز لها اختباراتها (yesterday-failures.test.ts).
بلا مفاتيح: تُقيَّم الحالات الحتمية فقط والباقي «متخطّى» برسالة واضحة. **`npm test` يشمل الجزء الحتمي** (نموذج مبرمج: الردود الصحيحة تنجح كلها، والأخطاء الحقيقية تفشل بالسبب الصحيح) — يبقى أخضر بلا شبكة.

**قاعدة PRs البوت نفسه**: `.github/workflows/evals.yml` يشغّل على كل PR: `tsc` + `npm test` دائماً، و`npm run eval` على النموذج الحقيقي إذا وُجد سرّا `GEMINI_API_KEY`/`NVIDIA_API_KEY` في المستودع، ويكتب تعليقاً واحداً على الـ PR يبدأ بـ `Eval score: NN%` (يُحدَّث مع كل commit). `EVAL_MIN_SCORE` (متغير مستودع) يجعل الـ job يفشل تحت الحد.
قبل «نعم N» على دمج PR للبوت: افتح رابط الـ PR وتأكد أن فحص **Evals** أخضر وأن الدرجة لم تنزل عن السابقة؛ أي تعثّر جديد يُضاف حالةً في `seed-cases.ts` بنفس الـ PR. (عرض الدرجة داخل معاينة الدمج نفسها مؤجَّل: التعليق يصل بعد دقائق من فتح الـ PR، ومعاينة الدمج تُرسل فوراً.)
ملاحظة: PRs التي يفتحها `GITHUB_TOKEN` لا تُطلق `pull_request` workflows — شغّلها يدوياً (Actions ← Evals ← Run workflow برقم الـ PR) إن لم يظهر الفحص.

**نموذج خطوة الفهم**: `LLM_UNDERSTAND_PROVIDER=gemini` ينقل فهم الرسائل النصية وحده إلى Gemini (بقية الخطوات والصوت كما هي، وجواب «أي مودل أنت» يعكس ذلك). فارغ = السلوك الحالي.
**رفض مخرجات النموذج**: كل مخرج JSON/schema مرفوض يُسجَّل في `llm_rejections` (المزوّد، النموذج، المحاولة، الخطأ، مقتطف) — ونسبة الرفض لكل نموذج في `GET /api/dash/selfreview` (مع آخر المراجعات وحالات التقييم، قراءة فقط).

## قروبات واتساب (منشن المالك فقط)
البوت يقرأ من القروب **فقط** رسالة المالك التي تذكر رقم البوت (@). أي رسالة أخرى في القروب تُتجاهل ولا تُحفظ.
يجهّز الرد/الإجراء ويرسل طلب موافقة في تيليجرام الخاص (أزرار ✅/❌)، وبعد "نعم" ينشر الرد في القروب.
عقد الوسيط المفترض (يحتاج دعماً في وسيط واتساب):
- ويبهوك الرسالة الواردة يضيف: `is_group`, `group_jid` (ينتهي بـ `@g.us`), `group_name`, `mentioned_bot`, و`from` = رقم المرسل داخل القروب.
- `POST /api/v1/messages` يقبل `{from, to: "<jid>@g.us", kind:"text", text, group:true}`.
